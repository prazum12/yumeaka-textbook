第4章

敵とゲームオーバー 〜ゲームらしいルール〜

📅 第4回の講習で使います（日付が決まったらここに記載）
💻 使っているPC:

🎯 この章でできるようになること

  • 穴に落ちたら、ステージの最初からやり直しになるようにできる
  • オブジェクト変数を使って、左右に往復する敵を作れる
  • 条件を2つ組み合わせて「上から踏んだら倒す」を作れる
  • イベントの順番が結果を変えることを説明できる

※ 前回のプロジェクトが開けない・壊れてしまった人は、講師を呼んでね。
この章は、Player・地面・カメラのイベントがあれば始められます（コインとスコアは後から追いつけばOK）。

4-1. ゲームらしいルールを考えよう

今のゲームは、穴に落ちてもずっと落ち続けるし、こわいものが何もありません。
「失敗することがある」から、ゲームはドキドキして楽しくなります。
この章で作るルールはこの3つ。

ルール条件（もし〜なら）アクション（〜する）
落ちたらやり直しPlayerが画面のずっと下まで落ちたStage1を最初からやり直す
踏んだら倒せるPlayerが落ちながらEnemyにさわったEnemyを消して、Playerを少し跳ねさせる
当たったらやり直しPlayerが（それ以外の形で）EnemyにさわったStage1を最初からやり直す

4-2. 穴に落ちたらやり直しにしよう

第1章の課題3で調べたように、GDevelopでは下へ行くほどYの数字が大きくなります。
だから「PlayerのYが、いちばん低い地面よりもっと大きくなった」＝「穴に落ちた」と判断できます。

1落ちたと判断するYの数字を決める

シーンエディタで、いちばん低い地面を選んでプロパティの Y を見ます。
その数字より300くらい大きい数を、「落ちた」と判断するラインにしよう。
たとえば地面のYが 600 なら、ラインは 900 です。

2条件「PlayerのYがラインより大きい」を作る

イベントシートで「Add a new event」→「Add condition」→ y position と検索。
Player のY座標を比べる条件（「Y position」など）を選び、Object に Player、比べ方を「> (greater than)」（より大きい）、値に決めたラインの数字を入れて「OK」。

📷 条件選択画面でY positionを選び、Player／>／900を指定しているところ
ch4-01_position-condition.png
3アクション「Stage1をやり直す」を作る

「Add action」→ scene と検索して「Change the scene」（シーンを切り替える）を選びます。
シーン名に Stage1 を選んで「OK」。
今いるシーンと同じシーンに切り替えると、シーンが最初からやり直しになります。

📷 アクション選択画面でChange the sceneを選び、Stage1を指定しているところ
ch4-02_change-scene-action.png
落ちたらやり直し
条件The Y position of Player > 900
アクションChange the scene to Stage1

Previewでわざと穴に落ちてみよう。
スタート地点に戻れば成功！
取ったコインも元に戻り、Score も 0 からになっているはずです（シーンごとやり直しになるため）。

4-3. 敵（Enemy）を用意しよう

1敵の素材を追加する

「Add a new object」からアセットストアで enemy や slime や monster と検索します。
横から見た敵を選んで追加し、名前を Enemy にしよう。
地面の上、少し進んだ場所に1体置きます。

📷 アセットストアでenemyと検索し、敵の素材を選んでいるところ
ch4-03_asset-store-enemy.png
2Enemy にも Platformer character をつける

敵も地面の上を歩いてほしいので、Enemy にも「Platformer character」ビヘイビアをつけます。
ただし、このままだとキミのキー操作で敵まで動いてしまいます。
ビヘイビアの設定にある「Default controls」（いつものキー操作）のチェックを外しておこう。
ついでに 最高速度（Max. speed など）を Player より小さい数（半分くらい）にしておくと、のんびり歩く敵になるよ。

📷 EnemyのPlatformer character設定。Default controlsのチェックを外し、Max. speedを小さくしたところ
ch4-04_enemy-default-controls.png

4-4. 敵に「今どっち向きか」を覚えさせよう

敵を左右に往復させるには、敵ごとに「今、右へ進んでいるか」を覚えておく必要があります。
第3章ではシーン全体で1つの箱（シーン変数）を使いましたが、今回は敵1体ずつに持たせる箱、オブジェクト変数を使います。

オブジェクト変数 … オブジェクトの1体1体が、それぞれ自分用に持っている箱。
敵が3体いれば、箱も3つ。
だから「この敵は右へ、あの敵は左へ」と、別々に動かせるんだ。
Boolean（ブーリアン） … 「true（はい）」か「false（いいえ）」の2つだけを入れられる変数の種類。
「右へ進んでいる？」→ はい／いいえ、のような質問の答えを覚えるのにぴったり。
1Enemy にオブジェクト変数 GoingRight を作る

Enemy をダブルクリックして、上のタブから「Variables」（変数）を開きます。
「Add a variable」で、名前を GoingRight、種類（Type）を Boolean、値を true にして「Apply」。
これで「最初は右へ進む」敵になります。

📷 EnemyのVariablesタブで、GoingRight（Boolean、true）を追加したところ
ch4-05_object-variable.png

4-5. 折り返しの目印を置こう

敵が「どこで向きを変えるか」の目印を置きます。
目印にさわったら向きを変える、というルールにするんだ。

1目印のオブジェクトを2つ作る

アセットストアから、小さな看板や矢印など目印になりそうな素材を追加して、名前を TurnLeft にします。
もう1つ別の素材（同じ素材でもOK）を追加して、名前を TurnRight にしよう。
目印にはビヘイビアをつけません。

2敵の通り道の両はしに置く

敵が歩いてほしい範囲の右はしに TurnLeft、左はしに TurnRight を置きます。
敵と同じ高さ（地面の上）に置いて、敵が歩いてきたら必ず重なる位置にしよう。

📷 地面の上に、Enemyをはさんで左にTurnRight、右にTurnLeftを置いたシーン
ch4-06_turn-markers-placed.png
3ゲームが始まったら目印をかくす

目印はプレイヤーに見えなくていいので、ゲームが始まった瞬間にかくします。
「Add a new event」→「Add condition」→ beginning と検索して「At the beginning of the scene」（シーンの始まり）を選びます。
アクションは hide と検索して「Hide」（かくす）を選び、TurnLeft に。
同じイベントにもう1つ「Hide」を足して、TurnRight もかくそう。

目印をかくす
条件At the beginning of the scene
アクションHide TurnLeft
Hide TurnRight
📷 At the beginning of the sceneとHideアクション2つでできた、目印をかくすイベント
ch4-07_hide-markers-event.png

4-6. 敵を往復させるイベントを作ろう

いよいよ敵を動かします。
Default controls を外した敵は、自分では動きません。
そこで、イベントで「右キーが押されたふり」をさせて動かします。

1「右へ進んでいるなら、右キーを押したふり」

「Add a new event」→「Add condition」→ variable と検索して、オブジェクト変数の値を調べる条件を選びます。
Object に Enemy、変数に GoingRight、値に true を指定して「OK」。

📷 条件選択画面で、EnemyのGoingRightがtrueかどうかを調べる条件を設定しているところ
ch4-08_enemy-variable-condition.png

アクションは simulate と検索して、Platformer character の「Simulate right key press」（右キーを押したふり）を選び、Object に Enemy を指定。

📷 アクション選択画面でSimulate right key pressを選び、Enemyを指定しているところ
ch4-09_simulate-key-action.png
2「左へ進んでいるなら、左キーを押したふり」

同じようにイベントをもう1つ。
条件は Enemy の GoingRight が false、アクションは「Simulate left key press」です。

3目印にさわったら向きを変える

さらにイベントを2つ作ります。
条件は「Collision」で Enemy と TurnLeft、アクションはオブジェクト変数を変えるアクションで GoingRight を false にします。
もう1つは Enemy と TurnRight のCollisionで、GoingRight を true に。

敵の往復（4つのイベント）
条件AEnemy の GoingRight が true
アクションSimulate right key press（Enemy）
BEnemy の GoingRight が false
Simulate left key press（Enemy）
CEnemy is in collision with TurnLeft
Enemy の GoingRight を false にする
DEnemy is in collision with TurnRight
Enemy の GoingRight を true にする
📷 敵の往復の4つのイベント（A〜D）が並んだイベントシート
ch4-10_enemy-events-done.png

Previewで、敵が目印のあいだを行ったり来たりすれば成功！
敵の向き（絵の左右）も変えたい人は、第3章のキャラの向きと同じように「Flip the object horizontally」をイベントAとBに足してみよう。

4-7. 踏んだら倒す・当たったらやり直し

最後に、Playerと敵がさわったときのルールです。
ポイントは「上から踏んだのか、横からぶつかったのか」をどう見分けるか。
答えは、Playerが落ちている最中にさわったら「踏んだ」とみなすこと。

1条件を2つ重ねた「踏んだ」イベントを作る

「Add a new event」で、1つ目の条件に「Collision: Player と Enemy」を入れます。
同じイベントの左側で、もう一度「Add condition」を押して、falling と検索。
Platformer character の「Is falling」（落ちている）を選び、Object に Player を指定します。
1つのイベントに条件を2つ並べると、「両方ともYESのときだけ」アクションが実行されます。

📷 条件選択画面でIs fallingを選び、Playerを指定しているところ
ch4-11_is-falling-condition.png
2「敵を消して、跳ねる」アクションを入れる

アクションは3つです。

  • 「Delete an object」で Enemy を消す
  • allow と検索して、Platformer character の「Allow jumping again」（もう一度ジャンプできるようにする）を Player に
  • simulate と検索して、「Simulate jump key press」（ジャンプキーを押したふり）を Player に

2つ目のアクションがないと、空中ではジャンプできないので跳ねてくれません。

3そのすぐ下に「当たったらやり直し」を作る

「踏んだ」イベントのすぐ下に、もう1つイベントを作ります。
条件は「Collision: Player と Enemy」だけ、アクションは「Change the scene: Stage1」。

Playerと敵（この順番が大事！）
条件EPlayer is in collision with Enemy
Player is falling
アクションDelete Enemy
Allow jumping again（Player）
Simulate jump key press（Player）
FPlayer is in collision with Enemy
Change the scene to Stage1
📷 踏んだら倒す（E）と当たったらやり直し（F）の2つのイベントが上下に並んだイベントシート
ch4-12_stomp-events-done.png

🚨 イベントの順番が大事なワケ

イベントは上から順番にチェックされます。
上から踏んだときは、先にイベントEで敵が消えるので、すぐ下のイベントFでは「さわっている敵」がもういません。
だから、やり直しにならずにすむんだ。
もしEとFの順番が逆だと、踏んだ瞬間にFが先に実行されて、やり直しになってしまいます。
イベントはドラッグで上下に並べかえられるよ。

4Previewで確かめて保存する

敵を上から踏むと消えて、Playerがぴょんと跳ねる。
横からぶつかるとスタートに戻る。
両方できれば大成功！
Ctrl + S⌘ + S で保存しよう。

4-8. 💪 やってみよう

課題1: 敵を増やそう

ステージのほかの場所にも敵を置こう。
それぞれの敵の両はしに、TurnLeft と TurnRight を置くのを忘れずに。
イベントは追加しなくても、新しい敵も往復するはず。
なぜイベントを増やさなくていいのか、説明できたら合格。

ヒントを見る

イベントは「Enemy という設計図から作ったもの全部」に効くよ。
そして GoingRight はオブジェクト変数なので、敵1体ずつが自分の箱を持っている。
だから、それぞれ別々に往復できるんだ。

課題2: トゲを作ろう

さわったらやり直しになる Spike（トゲ）を作って、ステージに置こう。
トゲは踏んでもダメ、という点が敵とのちがいです。

ヒントを見る

イベントFとほとんど同じイベントで作れるよ。
さわる相手を Enemy から Spike に変えるだけ。

課題3（チャレンジ）: 速さのちがう敵を作ろう

素早く動く敵 FastEnemy を作ってみよう。
見た目も変えて、「この敵は速い！」とわかるようにできたら合格。

ヒントを見る

新しいオブジェクトにすると、イベントA〜Fをもう一度作る必要があります。
イベントをコピーして、Enemy の部分を FastEnemy に書きかえるとラク。
速さはビヘイビアの最高速度（Max. speed など）で変えられるよ。

4-9. 🚨 つまずきポイント集

自分が矢印キーを押すと、敵まで一緒に動く

原因: Enemy の Platformer character で「Default controls」のチェックが入ったまま。

直し方: Enemy のビヘイビア設定で、Default controls のチェックを外して「Apply」。

敵が目印で折り返さない（通り過ぎて落ちていく）

原因1: 目印が敵の通り道と重なっていない（高さがずれている、地面にうまっている）。
→ 目印を、敵とちょうど同じ高さに置き直そう。

原因2: TurnLeft と TurnRight を逆に置いている。
→ 右はしが TurnLeft、左はしが TurnRight だよ。

原因3: イベントCとDで、true と false が逆になっている。

上から踏んでも、やり直しになってしまう

原因1: 「当たったらやり直し」のイベントFが、イベントEより上にある。
→ イベントをドラッグして、Eを上・Fを下にしよう。

原因2: イベントEの条件に「Player is falling」が入っていない、または別のイベントに分かれている。
→ 2つの条件が同じイベントの左側に並んでいるか確認しよう。

穴に落ちても、やり直しにならない

原因: Yの比べ方が逆（< にしている）、またはラインの数字が大きすぎる。

直し方: 「> (greater than)」になっているか確認しよう。
下へ行くほどYは大きくなる、を思い出してね。
ラインは「いちばん低い地面のY＋300」くらいが目安です。

Previewで目印が見えてしまう

原因: 目印をかくすイベントがない、または条件が At the beginning of the scene になっていない。

直し方: 4-5の手順3のイベントを確認しよう。

💡 15分たっても直らないときは、次の「AIを味方につけよう」の方法で相談してみよう。

4-10. 🤖 AIを味方につけよう

イベントが増えてきたら、AIに相談するときは関係するイベントだけを、上からの順番どおりに書き写そう。
今回のように「順番」が原因のバグもあるからです。

この章でのAIの使い所

✅ 良い使い方 — 自分で15分考えてわからなかったら聞く

  • 順番のバグ探し: イベントを順番どおりに書き写して、どこで問題が起きているか一緒に追いかけてもらう
  • しくみの理解: 「オブジェクト変数とシーン変数のちがい」など、説明できるようになるまで聞く

そのままコピペで使えるプロンプト（AIへの指示文）の例:

ブラウザ版のGDevelopでアクションゲームを作っている中学生です。
敵を上から踏んで倒したいのに、踏むとステージの最初に戻ってしまいます。
イベントは上から順に次のとおりです。
イベント1: 条件「Player is in collision with Enemy」／アクション「Change the scene to Stage1」
イベント2: 条件「Player is in collision with Enemy」「Player is falling」／アクション「Delete Enemy」
答えを言わずに、原因に気づけるヒントをください。
GDevelopの「シーン変数」と「オブジェクト変数」のちがいを、クラスの持ち物にたとえて説明してください。
敵ごとに向きを覚えさせるとき、どちらを使うべきかも教えてください。
